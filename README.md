# TVBox Manager：站点探测与整合配置

基于 [eastar23/tvbox-manager](https://github.com/eastar23/tvbox-manager) 修改，供 NAS 上管理 FongMi/TVBox 配置。导入多份 JSON 配置后，服务把站点、解析、直播和相关规则合成**一份配置**，电视只需填写一个 NAS 地址。

## 部署

1. 将 `.env.example` 复制为 `.env`，修改 `SECRET_KEY` 和邀请码。
2. 在本目录运行 `docker compose up -d --build`。
3. 打开 `http://192.168.6.237:8089` 注册并登录；首个用户是管理员。默认 Compose 只绑定此局域网地址，若 NAS 地址不同，请修改 `docker-compose.yml` 的端口映射。
4. 添加需要合并的 TVBox JSON 配置地址。配置顺序决定全局选项的优先级，第一份配置提供默认选项。
5. 新站点进入“未分类”并默认停用。在“站点管理”中筛选、探测并选择需要的站点，点击“启用”；也可以使用每行的启用开关。左侧按分组浏览，“分类审核”“配置来源”“模型设置”有各自独立的入口。
6. 将页面显示的 `/api/subscribe/用户名.json` 地址填入 FongMi 的点播配置。

登录时默认勾选“30 天内保持登录”；取消勾选则关闭浏览器后需重新登录。服务仅保存带签名的会话 Cookie，不在浏览器保存密码。

数据保存在 `./data`；更新代码后重新执行 `docker compose up -d --build`。部署时使用本地构建的镜像，避免拉取上游镜像覆盖这些修改。

## 探测说明

- 标准 CMS 站点（`type=0/1/4`，XML 或 JSON）会实际搜索指定关键词、读取详情。若详情给出可直接访问的 HLS 地址，还会读取播放列表和一个媒体分片，显示搜索、详情、首包延迟和采样速度。
- 接口正常返回空搜索列表时显示“可达 · 无搜索匹配”，可换一个适合该站点的词再测，不计入“探测失败”。旧版无法区分空结果与无效响应的记录显示“旧结果待重测”，不会被快捷失败选择选中。
- Spider/JAR、JavaScript、Python 站点依赖电视端运行环境。有独立 HTTP 脚本或接口地址时，NAS 可测该资源的响应延迟，显示“资源可达”；这并不表示站点搜索或播放可用。没有独立地址时显示“需电视端验证”。批量探测会逐个处理当前筛选列表中的站点。
- 这些结果只代表 NAS 当时的网络。搜索延迟与资源延迟分别排序；每行显示探测时间，“详情”可查看搜索词、失败原因和其他指标。批量探测可以停止后续任务。
- 更新或更换配置 URL 时，相同 `key` 的站点保留启用选择和分组，未变化站点保留探测结果；新增站点默认停用、未分类。读取新地址失败会保留原配置，成功时显示新增、移除、变更数量。订阅使用最近一次成功保存的配置。

## 批量与分组

- **复选框用于选择，启用开关决定订阅是否收录。** 选择站点后，可统一启用、停用、移组或探测。快速选择支持探测失败、需电视验证、CMS 和 Spider。
- 所有批量操作统一限定在当前分组与筛选结果内。“全选启用 / 全选停用”处理全部筛选结果，覆盖所有分页；表头复选框只选择本页，“选择全部筛选结果”覆盖所有分页。改变筛选或切换分组会清空待处理选择，避免操作隐藏站点。批量写入前显示数量及站点名称供确认。
- 首次打开新版分组界面时，会创建“综合影视、动漫、少儿、教育课堂、听书音频、音乐、体育直播、网盘搜索、无实际意义”预设组，并根据明显的站点名称给现有站点做一次初始分类。无法判断的站点留在“未分类”。之后新导入的站点始终先进入“未分类”，不会被自动移动。分组不会改变站点的启用状态。
- 可新建、编辑或删除分组；删除分组会把其中站点移到“未分类”。在站点行选择分组，或选中多项后统一移动，也可以把选中的站点拖到左侧目标分组。

## Jev 分类建议

在“模型设置”中选择 OpenRouter（默认）或 TypeSafe 官方，填写相应 API Key 和模型名。Key 在服务端加密保存，页面不会回显。OpenRouter 默认使用 `typesafe/jev-1.13` 和 Decisions API。

在“分类审核”选择某个分组后点击“分析当前分组”：模型会返回每个站点属于当前组的概率、建议目标组及各组概率。点击“按基线重新预选”，选出低于基线的站点，人工取消误判后确认移入“未分类”。在“未分类”中则预选达到基线的归类建议，每个目标组可分别全选、取消和确认。

改变基线不会自动改动勾选；确认一个类别也不会重置其他类别的人工选择。审核草稿保存在当前浏览器会话，页面刷新后可继续；新一轮模型结果会有独立草稿。模型分析本身不会修改分组或订阅。每次分析仅向所选服务发送站点名称、Key、来源、类型及分组名称和说明，不发送完整配置或登录凭据。

## 合并规则

按配置顺序汇总站点，并保留每个站点的参数。重复的站点 `key` 会加来源前缀，避免 FongMi 键冲突；这些键按全部已导入站点预分配，启停某个站点不会改掉另一个站点的键。移除来源或上游改变站点键仍可能影响电视收藏。原配置的 Spider 会赋给相应的 JAR 站点。相对脚本、JAR 和扩展文件地址会解析成原配置所在的绝对地址。解析、直播、规则、域名映射等列表按内容去重；第一份配置的其他全局选项优先。特殊私有配置格式可能需要单独适配。
